# FAB-403.3 · Suíte implícita não roda duas vezes

> ✅ Concluída · Subtarefa de FAB-403 · Etapa **E4 — Linha de produção de tarefas**

## A ideia

Rodar a suíte de testes uma vez por verificação, mesmo quando a tarefa pede a bateria inteira, que já inclui a suíte.

## O que foi feito

O `_management/ci.json` ganhou o campo `includes_suite`, com os comandos que já rodam a suíte por dentro (`mix factory.ci` e `mix factory.ci --fast`). `Factory.Criteria.Suite.append/2` não acrescenta a suíte implícita quando algum critério da tarefa usa um desses comandos, comparando pela mesma chave de comando da deduplicação.

## Por que surgiu

A deduplicação só une comandos idênticos. `mix test` (implícito) e `mix factory.ci` (declarado) são comandos diferentes, então a suíte rodava duas vezes na mesma verificação.

## Como foi feito

- Campo ausente, JSON inválido ou lista com elemento que não é texto viram lista vazia, ou seja, o comportamento anterior
- Uma lista malformada é inválida por inteiro, para não dispensar a suíte só em parte
- Comparação pela `command_key/1`, que normaliza `.bat`/`.exe` e `npm run`

## Critérios de aceite

- [x] Critério com comando listado em `includes_suite` dispensa a suíte implícita
- [x] Critério com outro comando mantém a suíte implícita
- [x] Campo ausente ou malformado mantém o comportamento anterior, sem erro

## Como verificar

```bash
mix test test/factory/criteria/suite_test.exs
```

## Onde está no código

`Factory.Criteria.Suite` (`lib/factory/criteria/suite.ex`) · `_management/ci.json`

## Commits

- perf(criteria): skip the implicit suite when a declared command already runs it, via includes_suite in ci.json (FAB-403.3)
