# FAB-407.2 · `mix factory.plan` cria o projeto como repositório git próprio, com opção `--domain`

> ✅ Concluída · Subtarefa de FAB-407 · Etapa **E4 — Linha de produção de tarefas**

## A ideia

Dar a cada projeto gerado o seu próprio repositório, para o commit de cada tarefa não cair no repositório da fábrica, e permitir escolher o domínio na criação.

## O que foi feito

`mix factory.plan "<pedido>" --project <nome>` cria um projeto novo em `generated-projects/<nome>` (relativo ao diretório atual, ignorado pelo git) e o inicializa como repositório próprio, com `.gitignore` e commit inicial. A opção `--domain <domínio>` define o domínio do projeto novo (padrão `software`); num projeto existente que tenha outro domínio, o planejamento é recusado com `{:error, {:domain_mismatch, guardado, pedido}}`.

## Por que surgiu

O projeto era criado ao lado do repositório da fábrica (`../<nome>`) e sem git: o commit feito ao fim de cada tarefa cairia no repositório errado. Além disso, escolher a trilha (software ou genérica) exigia criar o projeto à mão antes de planejar.

## Como foi feito

- `default_path/2` devolve `<base>/generated-projects/<nome>`
- `init_repository/2` roda `git init`, grava `.gitignore` e faz o commit inicial; um diretório que já tem `.git` é deixado em paz
- `get_or_create_project/3` devolve `{:ok, projeto}` ou o erro de domínio divergente; nada é promovido se o planejamento falha
- `generated-projects/` entra no `.gitignore` da fábrica

## Critérios de aceite

- [x] O projeto novo nasce em `generated-projects/<nome>` com repositório git próprio
- [x] `--domain` define o domínio do projeto novo
- [x] Domínio divergente num projeto existente recusa o planejamento
