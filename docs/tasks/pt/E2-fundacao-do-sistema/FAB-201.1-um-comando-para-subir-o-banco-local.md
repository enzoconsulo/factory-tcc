# FAB-201.1 · Um comando para subir o banco local

> ✅ Concluída · Subtarefa de FAB-201 · Etapa **E2 — Fundação do sistema**

## A ideia

Rodar o sistema inteiro só a partir deste repositório: o PostgreSQL local é criado, ligado e desligado por um comando do próprio projeto, sem nada para lembrar fora dele.

## O que foi feito

`mix factory.db` gerencia o cluster PostgreSQL local: `init` cria o cluster uma vez em máquina nova, `start` liga e espera até aceitar conexões, `status` diz se está no ar e `stop` desliga.

## Por que surgiu

Subir o banco dependia de saber onde o PostgreSQL estava instalado e chamar o `pg_ctl` à mão. O servidor não é serviço do Windows de propósito (só roda enquanto o sistema está em uso), então ligá-lo precisa ser um comando óbvio ao lado de `mix setup` e `mix phx.server`.

## Como foi construído

- `Factory.LocalDb` concentra as decisões; `Mix.Tasks.Factory.Db` só imprime o resultado
- Os binários vêm do mesmo `config :factory, :pg_bin` usado pela cópia de segurança (FAB-204); a pasta de dados, de `config :factory, :pg_data` (`FACTORY_PG_DATA`)
- `start` e `stop` são idempotentes: servidor já no ar não é ligado de novo
- Sem cluster, o `start` aponta para `mix factory.db init` em vez de falhar dentro do `pg_ctl`
- Toda função recebe quem executa o comando, então os testes conferem as decisões sem servidor real

**Exemplo:** `mix factory.db start` imprime `postgres started on 127.0.0.1:5432`; rodado de novo, imprime `postgres was already running`.

## Critérios de aceite

- [x] `mix factory.db start` deixa o PostgreSQL aceitando conexões em 127.0.0.1:5432
- [x] Ligar um servidor já no ar, ou desligar um já parado, não muda nada
- [x] Em máquina sem cluster, o `start` diz para rodar o `init`

## Como verificar

```bash
mix test test/factory/local_db_test.exs
mix factory.db start
mix factory.db status
```

## Onde fica no código

`Factory.LocalDb` · `Mix.Tasks.Factory.Db` · `config/config.exs`
