# FAB-403.1 · Timeout test independent of machine speed

> ✅ Done · Subtask of FAB-403 · Stage **E4 — Task production line**

## The idea

Make the test that proves the rerun of a criterion that timed out give the same result on any machine.

## What was done

The test "a timeout reruns ONCE and the rerun is counted" (`Factory.Criteria`) now runs a command that schedules a timer of about 28 hours and never ends by itself, with a 1 ms limit.

## Why it came up

The test used `git rev-parse --git-dir` with a 1 ms limit: the outcome depended on whether the command could finish inside that limit, and on fast machines it finished and the test failed. A command that never ends exceeds any short limit by construction, not by speed.

## How it was built

- Command `node -e setTimeout(function(){},99999999)` in place of `git rev-parse`
- `=>` avoided in the command: a bare `>` is already refused by the allowlist as chaining
- Only the test file changes; the code of `Factory.Criteria` stays the same

## Acceptance criteria

- [x] The test gives the same result on a slow and a fast machine
- [x] The timeout is rerun exactly once and the rerun is counted
