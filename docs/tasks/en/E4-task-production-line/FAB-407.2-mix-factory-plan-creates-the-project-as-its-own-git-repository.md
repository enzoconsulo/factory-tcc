# FAB-407.2 · `mix factory.plan` creates the project as its own git repository, with a `--domain` option

> ✅ Done · Subtask of FAB-407 · Stage **E4 — Task production line**

## The idea

Give each generated project its own repository, so each task's commit does not land in the factory's repository, and allow choosing the domain on creation.

## What was done

`mix factory.plan "<request>" --project <name>` creates a new project in `generated-projects/<name>` (relative to the current directory, git-ignored) and initialises it as its own repository, with a `.gitignore` and an initial commit. The `--domain <domain>` option sets the new project's domain (default `software`); on an existing project with a different domain, planning is refused with `{:error, {:domain_mismatch, stored, requested}}`.

## Why it came up

The project used to be created next to the factory repository (`../<name>`) and without git: the commit made at the end of each task would land in the wrong repository. Also, choosing the track (software or generic) meant creating the project by hand before planning.

## How it was built

- `default_path/2` returns `<base>/generated-projects/<name>`
- `init_repository/2` runs `git init`, writes `.gitignore` and makes the initial commit; a directory that already has `.git` is left alone
- `get_or_create_project/3` returns `{:ok, project}` or the domain-mismatch error; nothing is promoted if planning fails
- `generated-projects/` goes into the factory's `.gitignore`

## Acceptance criteria

- [x] The new project is created in `generated-projects/<name>` with its own git repository
- [x] `--domain` sets the new project's domain
- [x] A different domain on an existing project refuses planning
