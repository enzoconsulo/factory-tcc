# FAB-406.1 · Default per-task estimate recalibrated

> ✅ Done · Subtask of FAB-406 · Stage **E4 — Task production line**

## The idea

Bring the default estimate of the spending ceiling closer to the real cost of a whole task, so the ceiling does not underestimate the next task.

## What was done

`Factory.Budget` now declares a new starting value for the per-completed-task estimate, used while the round has measured nothing yet. The documentation and the doctest follow the new value.

## Why it came up

The estimate calibrates itself from the measured mean per completed task, but the starting value decides the first tasks of a round. A low starting value lets the ceiling accept a task that does not fit; the value was recalibrated to reflect the cost of a whole task.

## How it was built

- `@default_estimate` recalibrated in `Factory.Budget`; the formula and the ceiling behaviour do not change
- Doctest of `estimate_next_task([])` and test of `default_estimate/0` updated

## Acceptance criteria

- [x] With no measurement, the estimate of the next task is the declared value
- [x] With measurements, the measured mean still rules
