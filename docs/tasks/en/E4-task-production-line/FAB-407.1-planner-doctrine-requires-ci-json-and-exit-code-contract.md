# FAB-407.1 · Planner doctrine: ci.json in the foundation and the exit-code contract

> ✅ Done · Subtask of FAB-407 · Stage **E4 — Task production line**

## The idea

Make the planner deliver, from the first task, the file the rest of the factory depends on, and plan criteria the mechanical runner can decide.

## What was done

`priv/doctrine/planner.md` gained two sections. The first requires that, in a new project (no `_management/ci.json`), the FIRST task is the foundation and declares the file in `areas` and in a criterion that creates it, with `ecosystem` and at least the `tests` stage. The second fixes the `command` contract: it runs without a shell, as argv split on spaces, and passes if and only if it exits with code 0.

## Why it came up

The factory takes the implicit suite command and the command prefixes the agent may run (including the dependency installer) from `ci.json`; without it the next agent cannot even install a dependency. And a criterion whose EXPECTED behaviour is to fail ("invalid input is refused") cannot have the failing command itself as its `command`: the non-zero exit would be read as a wrong delivery. It becomes a test that ASSERTS the failure and exits 0.

## How it was built

- Section "The first task of a new project is the foundation, and it creates `_management/ci.json`" with the minimal format (Node as example)
- Section "The `command` contract" with a wrong and a right example
- Only the doctrine changes; the plan's JSON format and validation rules stay the same

## Acceptance criteria

- [x] The doctrine requires `ci.json` in the first task of a new project
- [x] The doctrine explains that a criterion passes only on exit code 0 and how to handle an expected failure
