# FAB-305.2 · Long-name root and a measured action cap

> ✅ Done · Subtask of FAB-305 · Stage **E3 — The agent and its tools**

## The idea

Close two gaps left by FAB-305.1: the CLI failing as a whole when the project folder arrives with a Windows short name, and the 60-action cap per dispatch, which had no measurement behind it.

## What was done

`Factory.Provider.ClaudeCLI.long_root/2` expands Windows 8.3 short segments (for example `ENZOCO~1`) to the long name before the CLI starts. The CLI's working directory, the tool server and the after-the-fact audit now use the same long root. A root with no short segment passes untouched, without asking the OS; a short root that cannot be expanded is refused before the CLI starts, with `{:short_path_root, root}`. The action cap stays at 60, now with its source recorded in the code.

## Why it came up

With a short-name root, the CLI does not recognise its own working directory in the paths it checks: it asks for manual approval on every file, nobody answers in non-interactive mode, and the session fails after it has run. On Windows the temp folder (`%TEMP%`) already comes with a short name, so the case is not rare; the FAB-305.1 server mode escaped it for file tools, but the shell is still the CLI's and runs in the same folder. The 60 cap was checked against 605 real dispatches (September and October 2026 logs), counting file actions per dispatch:

| role | p95 | max |
|---|---|---|
| verifier | 14 | 18 |
| reviewer | 13 | 17 |
| documenter | 18 | 20 |
| planner | 25 | 26 |
| builder | 33 (p99 53) | 65 |

Only 1 of the 605 dispatches went past 60: the cap catches a runaway loop without cutting normal work. Checked against the real CLI with the temp folder under a short name: in native mode the session runs through and the path already arrives with the long name; in server mode, with a second model (2 sessions), both completed with the outside write refused first and the report received.

## How it was built

- The long name comes from Windows' own PowerShell `Get-Item`, with no compiled helper and no new dependency; the root goes through the environment, never into the command text
- The result is accepted only if it exists as a folder; an error or a missing folder becomes `short_path_root`
- Outside Windows, `~1` is an ordinary name and nothing changes

## Acceptance criteria

- [x] A root with no short segment passes untouched, without asking the OS
- [x] A root with a short segment reaches the CLI with the long name
- [x] A short root that cannot be expanded is refused before the CLI starts
- [x] The action cap has its measurement recorded in the code
