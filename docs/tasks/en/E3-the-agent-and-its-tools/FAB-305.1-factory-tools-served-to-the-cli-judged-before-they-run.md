# FAB-305.1 · The factory's tools served to the CLI, judged before they run

> ✅ Done · Plus of FAB-305 · Stage **E3 — The agent and its tools**

## The idea

Give the CLI path (subscription) the same step-by-step governance as the API path: each action judged by the factory BEFORE it happens, instead of audited afterwards.

## What was done

The new `Factory.Provider.ClaudeCLI.ToolServer` opens, per dispatch, an MCP server on `127.0.0.1` (free port, secret path) that serves the CLI the SAME tool functions `Factory.Agents.Loop` receives (`read`, `list`, `search`, `write`, `edit`, `report_result`). The adapter turns off the CLI's own file tools (`--tools`) and approves only the factory's (`--allowedTools`, `--strict-mcp-config`, `--mcp-config`). The loop now hands its tools to the provider in the `:full_agent` family too. A refusal (for example, `outside_confinement`) goes back to the agent as an error result; the action cap (`max_actions`, default 60) refuses every action past it, except `report_result`, and the session ends as `:max_turns`. The after-the-fact audit still covers the CLI's own tools.

## Why it came up

A plus, outside the original FAB-305 package. On the CLI path the CLI itself ran the tools and the factory only audited the output at the end: a write outside the project was found with the session already run, and the whole session became an error, including the correct work. The turn cap counted the session as a single turn, and the CLI had no report tool. Measured against the real CLI, on the same task (edit a file, try to write outside the project, create another file and report), 4 sessions per mode: before, 4 of 4 sessions thrown away and no report; after, 4 of 4 completed with the outside write refused before it happened and the report received. The session also got smaller: about 15.1 thousand tokens read from cache against 34.7 thousand, and 4.3 thousand written against 7.4 thousand.

## How it was built

- Only the MCP subset the CLI needs (`initialize`, `tools/list`, `tools/call`, `ping`), answered as plain JSON on the Bandit the project already uses; no new dependency
- The server serves the functions the caller already bound: from E5 on, the task `areas` and the report collector hold on the CLI too, unchanged
- The shell is not served: a command cannot be judged by its path, so it stays the CLI's, with the sandbox or per-prefix rules
- `config :factory, :claude_cli_tool_server, false` goes back to the previous mode
- `priv/probes/cli_tool_server.exs` measures both modes against the real CLI

## Acceptance criteria

- [x] A write outside the project is refused before it happens and the session goes on
- [x] The CLI only announces the factory's tools for files
- [x] Past the cap every action is refused, except the report
- [x] A call to the factory's tool is not audited again after the session
