# FAB-201.1 · One command to start the local database

> ✅ Done · Subtask of FAB-201 · Stage **E2 — System foundation**

## The idea

Run the whole system from this repository alone: the local PostgreSQL is created, started and stopped by a project command, with nothing to remember outside the project.

## What was done

`mix factory.db` manages the local PostgreSQL cluster: `init` creates it once on a new machine, `start` starts it and waits until it accepts connections, `status` reports whether it is up, and `stop` shuts it down.

## Why it came up

Starting the database depended on knowing where PostgreSQL was installed and calling `pg_ctl` by hand. The server is not a Windows service on purpose (it runs only while the system is in use), so starting it has to be one obvious command next to `mix setup` and `mix phx.server`.

## How it was built

- `Factory.LocalDb` holds the decisions; `Mix.Tasks.Factory.Db` only prints the outcome
- Binaries come from the same `config :factory, :pg_bin` used by the backup (FAB-204); the data directory from `config :factory, :pg_data` (`FACTORY_PG_DATA`)
- `start` and `stop` are idempotent: an already running server is not started again
- Without a cluster, `start` points to `mix factory.db init` instead of failing inside `pg_ctl`
- Every function receives the command runner, so the tests check the decisions without a real server

**Example:** `mix factory.db start` prints `postgres started on 127.0.0.1:5432`; run again, it prints `postgres was already running`.

## Acceptance criteria

- [x] `mix factory.db start` leaves PostgreSQL accepting connections on 127.0.0.1:5432
- [x] Starting an already running server, or stopping a stopped one, changes nothing
- [x] On a machine without a cluster, `start` says to run `init`

## How to verify

```bash
mix test test/factory/local_db_test.exs
mix factory.db start
mix factory.db status
```
